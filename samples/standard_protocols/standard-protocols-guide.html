MCP · A2A 표준 연동 가이드

ACP 서버는 환경변수 구성만으로 MCP(Model Context Protocol)와 A2A(Agent2Agent) 표준을 양방향으로 지원한다. 본 문서는 logosai/samples/standard_protocols의 예제 코드를 기준으로, 각 구성요소의 역할과 실제 호출 경로를 설명한다.

연동에는 두 방향이 있으며, 본 문서 전체에서 다음 용어를 사용한다.

  • 표준 노출(Expose) — 외부 표준 클라이언트가 LogosAI의 에이전트를 사용한다. MCP 클라이언트(Claude Code, IDE)와 외부 조직의 A2A 에이전트가 ACP를 호출하는 방향.
  • 표준 소비(Consume) — LogosAI가 외부 표준 시스템을 사용한다. 외부 MCP 서버·파트너 A2A 에이전트를 ACP에 등록해 내부 에이전트와 동일한 방식으로 호출하는 방향.

1 · Background

설계 동기 — 통합 비용을 상수로 만들기

외부에 MCP로 구축된 도구 서버와 A2A로 노출된 파트너 에이전트가 각각 늘어난다고 할 때, 통상적인 접근은 시스템마다 전용 클라이언트 코드를 작성하는 것이다. 이 방식은 통합 비용이 연동 대상 수에 비례해 증가하고, 호출부 코드에 프로토콜 지식(tools/call과 message/send의 구분)이 퍼지는 문제가 있다. 표준을 채택하는 취지가 통합 지점에서 다시 무너지는 셈이다.

이를 피하기 위해 등록을 코드가 아닌 선언으로 옮겼다. JSON 선언에 주소와 프로토콜을 기재하면 ACP가 기동 시 discovery(tools/list 또는 agent-card 조회)를 수행해 해당 시스템을 가상 에이전트로 편입한다. 이후의 호출 문법은 내부 에이전트와 완전히 동일하다.

await internal_call("sample_tools",    "3 더하기 5는?")     # 실제 전송: MCP tools/call
await internal_call("partner_summary", "…요약해줘")         # 실제 전송: A2A message/send
await internal_call("file_agent",      "CLAUDE.md 찾아줘")   # 기존 내부 에이전트

세 호출의 형태가 동일하다는 점이 이 설계의 핵심이다. 프로토콜 분기는 Driver 계층 내부에만 존재하며, 호출부에는 나타나지 않는다. 그 결과 연동 대상이 N개로 늘어도 추가되는 것은 선언 N개뿐, 통합 코드는 늘지 않는다.

4 · Getting Started

실행 절차

# 터미널 1 — ACP를 표준 플래그와 샘플 편입 선언으로 기동 (데모 전용 포트 8899)
cd acp_server
ACP_ENABLE_MCP=true ACP_ENABLE_A2A=true ACP_ENABLE_EXTERNAL=true \
  ACP_EXTERNAL_CONFIG=../logosai/samples/standard_protocols/external_endpoints.sample.json \
  python standalone_acp_server.py --port 8899 --enable-auto-agent-selection

# 터미널 2 — 외부 역할의 샘플 서버 두 개
cd logosai/samples/standard_protocols
PORT=8901 python mcp_server_sample.py &
PORT=8902 python a2a_server_sample.py &

# 터미널 3 — 통합 데모
ACP_URL=http://localhost:8899 python acp_integration_demo.py

기동 로그에서 다음 두 줄이 확인되면 편입이 완료된 것이다.

외부 에이전트 편입: sample_tools (mcp, tools=2)
외부 에이전트 편입: partner_summary (a2a, tools=1)
운영 참고. discovery는 ACP 기동 직후 짧은 유예(기본 3초) 뒤에 수행된다. 샘플 서버를 그보다 늦게 띄우면 다음 refresh 주기(ACP_EXTERNAL_REFRESH, 기본 300초)까지 편입이 지연된다. 데모 환경에서는 샘플 서버를 먼저 띄우는 순서를 권장한다.

7 · Ask-and-Retry

되묻기 — 필수 인자를 알 수 없으면 묻는다

get_grid_forecast는 격자 좌표 nx·ny가 필수이지만 "격자 예보 알려줘"라는 요청에는 좌표가 없다. 이때 LLM이 임의의 값을 채워 넣는 것은 가장 나쁜 결과를 낳는다. 따라서 인자 추출 프롬프트에 "알 수 없는 값은 생략"을 명시하고, 필수값이 비어 있으면 외부 호출을 수행하지 않은 채 구조화된 질문을 반환하도록 했다.

실행을 중단 후 재개하는 방식(pause/resume)도 검토했으나, 정지된 실행 상태를 유지하는 복잡도에 비해 "정직하게 종료하고, 응답 수신 시 보존된 컨텍스트와 병합해 재실행"하는 구조가 단순하고 결정적이었다. A2A 명세의 input-required 모델이 정확히 이 형태이기도 하다. 질문 필드의 형식은 웹 프론트엔드의 InteractionField와 동일하게 맞춰 두어 추후 대화형 UI에 변환 없이 연결된다.

어댑터 계층은 단위 테스트 65건(9개 파일)으로 회귀를 고정했다. 외부 서비스 없이 검증할 수 있도록 자기 자신을 편입시키는 루프백 구성과, ACP 두 인스턴스를 상호 연결하는 연합 구성으로도 전 경로를 확인했다. 재현 절차는 docs/MCP_A2A_USAGE_GUIDE.md에 기록되어 있다.

알려진 현상. 최초 데모 실행에서 A2A 응답이 1회 비어 반환된 사례가 있다 (샘플 서버 포트 경합 시점으로 추정). 재실행 및 직접 호출에서는 재현되지 않았으나, 동일 증상 발생 시 참고할 것.
9 · Summary

원칙 요약

  • 외부 시스템 추가는 선언 한 항목이다. 연동을 위해 클라이언트 코드를 새로 작성하고 있다면 설계 의도에서 벗어난 것이다.
  • 호출부에 프로토콜이 드러나지 않아야 한다. 분기가 필요하면 Driver 내부로 한정한다.
  • 필수 인자를 알 수 없을 때 기본값으로 대체하지 않는다 — input-required로 질문한다.

mcp_server_sample.py는 실제 도구 서버의 골격으로 그대로 사용할 수 있다. 도구 구현을 채우고 선언 파일에 주소를 기재하는 시점에, 그 서버는 LogosAI의 에이전트가 된다.
