01 · Why

왜 표준인가 — 그리고 왜 게이트웨이인가

문제

표준을 써도 통합 비용이 선형 증가한다.

외부에 MCP로 만든 도구 서버가 3개, A2A로 만든 파트너 에이전트가 2개라면? 전통적 접근은 시스템마다 클라이언트 코드를 따로 작성한다 — 표준의 취지가 반감된다. 호출하는 쪽도 "이건 MCP니까 tools/call, 저건 A2A니까 message/send"를 알아야 한다.

해법 — ACP 게이트웨이

선언 1항목 = 편입 완료. 호출자는 프로토콜을 모른다.

외부 엔드포인트를 JSON 한 항목으로 선언하면 ACP가 discovery(tools/list · agent-card)를 수행해 가상 에이전트로 자동 편입한다. 이후 호출 문법은 로컬 에이전트와 완전히 동일하고, 프로토콜 전환은 Driver 내부에서 자동으로 일어난다.

# 세 호출의 문법이 완전히 동일하다 — 이것이 "자동전환"의 정의
await internal_call("sample_tools",    "3 더하기 5는?")      # → 실제로는 MCP tools/call
await internal_call("partner_summary", "…요약해줘")          # → 실제로는 A2A message/send
await internal_call("file_agent",      "CLAUDE.md 찾아줘")   # → 로컬 에이전트 (기존)
02 · Architecture

전체 아키텍처 — 두 개의 경계, 하나의 실행 관문

내부는 아무것도 바뀌지 않는다. 어댑터는 표준 노출(Expose)과 표준 소비(Consume) 두 경계에서 포맷만 번역하며, 모든 실행은 검증된 단일 관문 internal_call을 지난다.

MCP·A2A 클라이언트 (외부)
Claude Code · IDE · 파트너 에이전트
기존 클라이언트
logos_api · logos_web (무변경)
│ Expose: /mcp · /a2a · agent-card │ /jsonrpc · /stream (기존)
▼
ACP SERVER — 표준 어댑터(★신규, flag 기본 off) + 기존 핸들러
mcp_adapter · a2a_adapter · schema_mapper · task_store
▼ internal_call (단일 실행 관문 — 트레이싱·에러처리 기존 그대로)
86+ 로컬 에이전트
에이전트 코드 수정 0
★ 가상 에이전트 (ExternalAgentProxy)
"sample_tools"(MCP) · "partner_summary"(A2A)
│ Consume: Driver 자동전환
▼
외부 MCP 서버(:8901) · 외부 A2A 에이전트(:8902)
← 이 폴더의 샘플이 이 역할
03 · Samples — 외부 시스템 역할

샘플 서버 2개 — "편입될 외부 시스템"을 직접 만들어 본다

mcp_server_sample.py (:8901)

MCP Streamable HTTP 최소 구현 — POST /mcp에 JSON-RPC (initialize / tools/list / tools/call).

도구 2개:
▸ add(a, b) — 결정적 계산 데모
▸ get_grid_forecast(nx, ny) — 필수 인자가 있는 도구. 자연어에 좌표가 없으면 ACP가 되묻기(input-required)를 발동시키는 시나리오의 주인공.

a2a_server_sample.py (:8902)

A2A 최소 구현 — GET /.well-known/agent-card.json(discovery) + POST /a2a의 message/send → Task 반환.

"파트너사 문서 요약 에이전트" 역할: 받은 텍스트를 한 줄 요약으로 가공. 실제 파트너 조직의 A2A 에이전트가 이 자리에 오면 ACP는 선언 1항목으로 동일하게 편입한다.

편입 선언 — external_endpoints.sample.json

{ "endpoints": [
  { "id": "sample_tools",    "protocol": "mcp", "url": "http://localhost:8901/mcp", "enabled": true },
  { "id": "partner_summary", "protocol": "a2a", "url": "http://localhost:8902",     "enabled": true } ] }
이 JSON이 통합 작업의 전부다. ACP 기동 시 discovery가 자동 수행되어 list_agents에 type EXTERNAL 가상 에이전트로 나타난다 — 라우팅·조합·gap감지·트레이싱이 즉시 적용된다.
04 · Consume Flow

ACP가 외부를 호출하는 법 — 프로토콜 자동전환

사용자·에이전트·오케스트레이터 누구든 agent_id만 알면 된다. 아래는 통합 데모의 실측 흐름이다 (2026-07-02).

두 흐름의 왼쪽 절반(호출자→프록시)은 완전히 동일하다 — 다른 것은 Driver뿐. 새 표준(예: 향후 ANP)이 나와도 Driver 1개만 추가하면 전체 생태계가 그대로 재사용된다. 장애 시엔 endpoint별 CircuitBreaker가 열려 외부 장애가 내부 라우팅으로 전파되지 않는다.
05 · Ask-and-Retry

되묻기 — 모르면 지어내지 않고 묻는다

get_grid_forecast는 nx/ny가 필수인데 "격자 예보 알려줘"에는 좌표가 없다. 시스템은 조용한 기본값으로 날조하지 않고 A2A 표준 input-required 태스크로 구조화된 질문을 되돌려준다. 답이 오면 보존된 컨텍스트와 병합해 이어서 실행한다.

① "격자 예보 알려줘"
(좌표 없음)
→
② LLM 인자 매핑
날조 금지 프롬프트
→ nx/ny 생략
→
③ Task: input-required
fields = [nx:number, ny:number]
+ resume 컨텍스트 보존
④ 같은 taskId로 답
data part {nx:60, ny:127}
→
⑤ 병합 → 외부 도구 실행
LLM 불필요 (결정적)
→
⑥ Task: completed
"격자(60,127) 예보: 맑음, 26.5°C" (실측)

A2A 표면

input-required(비종결) + taskId continuation — 표준 네이티브

MCP 표면

stateless — isError + structuredContent.needs_input → 인자 채워 재호출

웹 UI (예약)

질문 필드가 InteractionField와 동일 형태 — 기존 form 다이얼로그에 변환 0으로 투입

06 · Expose Flow

반대 방향 — 외부가 ACP를 표준으로 소비한다

같은 ACP가 동시에 MCP 서버이자 A2A 에이전트다. 86+ 에이전트가 agents.json 메타데이터에서 자동 파생되어 노출된다 — 에이전트 코드 수정 0.

mcp_client_sample.py

표준 MCP 클라이언트 시퀀스:
① initialize (핸드셰이크)
② notifications/initialized (202)
③ tools/list → acp_query (router 모드: 도구 1개가 86+ 에이전트의 관문)
④ tools/call — agent_id 직접 지정
⑤ tools/call — 자동 라우팅 (TaskClassifier)

가장 짧은 실전: claude mcp add --transport http logosai http://localhost:8888/mcp

a2a_client_sample.py

외부 조직 에이전트의 협업 시퀀스:
① agent-card discovery — 카드 하나로 skills 전부 파악 (편입된 외부 시스템도 skill로 노출: 실측 119개)
② message/send → Task(completed) + artifacts(text·data)
③ tasks/get — TTL 내 조회
④ 되묻기 — input-required → continuation (S6의 클라이언트 측)

보안: 기본 flag off(라우트 자체가 없음) · ACP_STANDARD_API_KEY로 Bearer 강제 가능 · 관리 메서드(hot_register 등)는 표준 표면에서 -32601로 차단(테스트로 고정).
07 · Run It

직접 실행 — 3개 터미널이면 끝

cd <repo>/acp_server
ACP_ENABLE_MCP=true ACP_ENABLE_A2A=true ACP_ENABLE_EXTERNAL=true \
  ACP_EXTERNAL_CONFIG=<repo>/logosai/samples/standard_protocols/external_endpoints.sample.json \
  python standalone_acp_server.py --port 8899 --enable-auto-agent-selection

# 터미널 2 — 외부 역할 샘플 서버 2개
cd <repo>/logosai/samples/standard_protocols
PORT=8901 python mcp_server_sample.py &
PORT=8902 python a2a_server_sample.py &

# 터미널 3 — 통합 데모 (Consume 2종 + 되묻기 + Expose 자동 시연)

09 · Summary

요약 — 표준은 경계에, 지능은 내부에

Expose

86+ 에이전트가 agents.json에서 자동 파생되어 MCP 도구·A2A 스킬로 노출. 어떤 벤더의 LLM 앱이든 표준만 지원하면 연동 — 모델 비종속.

Consume

외부 표준 시스템 N개 = 선언 N항목 + 코드 0줄. 호출 문법은 로컬과 동일, 프로토콜 전환은 Driver가. 라우팅·조합·gap감지·트레이싱 자동 적용.

신뢰

모르면 지어내지 않고 묻는다(되묻기) · 외부 장애는 CircuitBreaker로 격리 · 외부 응답은 데이터로만 취급 · 기본 off로 회귀 0.

이 폴더의 샘플은 그대로 복사해 실제 외부 시스템의 골격으로 써도 된다 — mcp_server_sample.py에 도구를 채우면 그 순간 LogosAI의 에이전트가 된다.
